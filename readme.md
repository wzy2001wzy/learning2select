# Learning to Select: Query-Aware Adaptive Dimension Selection for Dense Retrieval


This project trains a **dimension predictor** that selects the most useful embedding dimensions for each query.  
Given precomputed query/document embeddings and relevance labels, the predictor learns a query-specific dimension ranking and evaluates retrieval performance under different **retained dimension**.
## Overview

The pipeline consists of three stages:

1. **Load data and precomputed embeddings**
2. **Generate soft oracle training labels**
3. **Train a predictor and evaluate it under different retained dimension**

The model is a simple linear predictor:

- Input: full query embedding
- Output: a score distribution over embedding dimensions

During evaluation, the predictor selects the top-ranked dimensions for each query, and retrieval is performed using only those dimensions.

## Prepare Embeddings

Before training or evaluation, you need to prepare **query embeddings** and **corpus embeddings** for each `(model, dataset)` pair.

This project does **not** compute embeddings internally.  
Instead, it expects all embeddings to be precomputed and stored as PyTorch tensor files.

Embeddings should be generated by first loading the **queries** and **corpus** from the standard BEIR dataset format, and then encoding them **in the same order as they are read**.  
This ordering is important because the training and evaluation pipeline assumes that each embedding row matches the corresponding query ID or document ID at the same position.

### How to prepare embeddings

For each dataset:

1. Load the BEIR dataset using the standard loader.
2. Read the query set and corpus.
3. Build ordered text lists from the loaded queries and corpus.
4. Encode the texts with your embedding model.
5. Save the resulting tensors with `torch.save(...)`.

### Example workflow

A typical workflow looks like this:

    from beir.datasets.data_loader import GenericDataLoader

    corpus, queries, qrels = GenericDataLoader(data_folder="path/to/dataset").load(split="train")

    query_ids = list(queries.keys())
    query_texts = [queries[qid] for qid in query_ids]

    corpus_ids = sorted(
        corpus,
        key=lambda k: len(corpus[k].get("title", "") + corpus[k].get("text", "")),
        reverse=True,
    )
    corpus_texts = [
        (corpus[doc_id].get("title", "") + " " + corpus[doc_id].get("text", "")).strip()
        for doc_id in corpus_ids
    ]

    # encode query_texts and corpus_texts with your embedding model
    # query_emb = ...
    # corpus_emb = ...

    # save with torch.save(query_emb, ...)
    # save with torch.save(corpus_emb, ...)

### Required files

For each model and dataset, the following files are expected:

    {base_emb_path}/{model_name}/{dataset_name}/train/queries_embeddings.pt
    {base_emb_path}/{model_name}/{clean_dataset_name}/test/queries_embeddings.pt
    {base_emb_path}/{model_name}/{clean_dataset_name}/test/corpus_embeddings.pt

Optional:

    {base_emb_path}/{model_name}/{clean_dataset_name}/train/corpus_embeddings.pt

If `train/corpus_embeddings.pt` is not provided, the script falls back to using the test corpus embeddings.

### Expected tensor format

Each embedding file must contain a single PyTorch tensor of shape:

    [num_items, dim]

Examples:

- query embeddings: `[num_queries, dim]`
- corpus embeddings: `[num_documents, dim]`

All embeddings for the same `(model, dataset)` pair must use the **same embedding dimension**.

### Example

For a model named `qwen-4b` and a dataset named `scifact`, the directory may look like:

    embeddings/
      qwen-4b/
        scifact/
          train/
            queries_embeddings.pt
            corpus_embeddings.pt
          test/
            queries_embeddings.pt
            corpus_embeddings.pt

### Important: row order must match IDs

The row order of each tensor must be aligned with the IDs used by the dataset loader.

Specifically:

- `train/queries_embeddings.pt` must follow the order of `list(queries_train.keys())`
- `test/queries_embeddings.pt` must follow the order of `list(queries_test.keys())`
- `corpus_embeddings.pt` must follow the order of the corpus IDs used at runtime `    corpus_ids = sorted(
        corpus_test,
        key=lambda k: len(corpus_test[k].get("title", "") + corpus_test[k].get("text", "")),
        reverse=True,
    )`

In this project, corpus embeddings are matched against a corpus ID list built from the test corpus.  
If the embedding row order and corpus ID order do not match, the script may still run, but the results will be incorrect.

## Important Arguments

The script is designed to train and evaluate one predictor for each `(model, dataset)` pair.

Below are the most important arguments.

### Required arguments

- `--models`  
  One or more model names.  
  These names are used to locate embedding files under `{base_emb_path}/{model_name}/...`.

- `--datasets`  
  One or more dataset names.  
  These names are used to locate dataset files and corresponding embeddings.

### Path-related arguments

- `--base-data-path`  
  Root directory of the BEIR-format datasets.

- `--base-emb-path`  
  Root directory of the precomputed embedding files.

- `--base-result-path`  
  Directory where evaluation result JSON files will be saved.

- `--save-dir`  
  Directory where trained predictor checkpoints will be saved.

- `--best-hyperparams-file`  
  JSON file containing the selected hyperparameters for each `(model, dataset)` pair.  
  The script reads `epoch` and `temp` from this file and trains once with those values. The `ckpt` field records a previous checkpoint path and is not used for this training run.

### Training-related arguments

- `--lr`  
  Learning rate for training the predictor.

- `--batch-size`  
  Batch size used during training.

- `--seed`  
  Random seed for reproducibility.

### Label generation arguments

- `--hard-negative-topk`  
  Number of top retrieved documents considered as the hard negative pool.

- `--num-negatives`  
  Number of negatives sampled for each query when generating soft oracle labels.

### Runtime arguments

- `--device`  
  Device used for training and evaluation.  
  Typical values are `cuda` or `cpu`.  
  If not specified, the script automatically uses CUDA when available.

- `--overwrite`  
  If this flag is provided, existing predictor checkpoints and result files will be overwritten.  
  Otherwise, existing runs are skipped.

## How to Run the Script

### Run a single model on a single dataset

    python train_and_eval.py \
      --models qwen-4b \
      --datasets scifact \
      --base-data-path /path/to/beir-dataset \
      --base-emb-path /path/to/embeddings \
      --best-hyperparams-file best_paths_hyperparams.json

### Run one model on multiple datasets

    python train_and_eval.py \
      --models qwen-4b \
      --datasets scifact nfcorpus fiqa \
      --base-data-path /path/to/beir-dataset \
      --base-emb-path /path/to/embeddings \
      --best-hyperparams-file best_paths_hyperparams.json

### Run multiple models on multiple datasets

    python train_and_eval.py \
      --models qwen-4b bge-large e5-base \
      --datasets scifact nfcorpus \
      --base-data-path /path/to/beir-dataset \
      --base-emb-path /path/to/embeddings \
      --best-hyperparams-file best_paths_hyperparams.json

In this case, the script runs all model-dataset combinations.

### Force overwrite existing results

    python train_and_eval.py \
      --models qwen-4b \
      --datasets scifact \
      --base-data-path /path/to/beir-dataset \
      --base-emb-path /path/to/embeddings \
      --best-hyperparams-file best_paths_hyperparams.json \
      --overwrite

### Run on CPU

    python train_and_eval.py \
      --models qwen-4b \
      --datasets scifact \
      --base-data-path /path/to/beir-dataset \
      --base-emb-path /path/to/embeddings \
      --best-hyperparams-file best_paths_hyperparams.json \
      --device cpu
